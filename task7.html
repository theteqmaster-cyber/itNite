1. Level 1 Data Flow Diagram (DFD)

This Level 1 DFD shows how data moves around in the tracking system. The IoT smart collars send real-time coordinates. The tracking engine compares these with boundaries. If the animal goes out of the grazing zone, alerts are sent to the farmer and logged. Administrators handle database registration entries for devices, farmers, and animals.

Figure 1: Level 1 DFD showing data flow and processing engines.

2. UML Class Diagram

This class diagram lays out the structure of our code. The abstract `User` class is extended by `Farmer` and `SystemAdmin`. Each `Farmer` has a collection of `Livestock`. Every `Livestock` is associated with one tracking `Device` (smart collar), which generates multiple `SensorData` records. If anything strange happens, `Alert` events are triggered for the animal and sent to the farmer.

Figure 2: UML Class Diagram showing attributes, operations, and relationships.

3. Java Implementation

Below is a direct Java implementation of three core classes from the UML blueprint: `Device`, `Livestock`, and `Farmer`.

3.1 Device Class

package com.iot.livestock; public class Device { private String collarId; private int batteryLife; private String status; // Constructor to boot up the device public Device(String collarId) { this.collarId = collarId; this.batteryLife = 100; this.status = "OK"; } // Method 1: Broadcast position coordinates to the network public boolean sendLocationData(double lat, double lng) { System.out.println("Collar " + this.collarId + " sending: Lat=" + lat + ", Lng=" + lng); return true; } // Method 2: Simulate power consumption public void drainBattery(int amount) { this.batteryLife = Math.max(0, this.batteryLife - amount); if (this.batteryLife < 15) { this.status = "LOW"; } if (this.batteryLife == 0) { this.status = "DEAD"; } } // Basic Getters public String getCollarId() { return collarId; } public int getBatteryLife() { return batteryLife; } public String getStatus() { return status; } }

3.2 Livestock Class

package com.iot.livestock; public class Livestock { private String animalId; private String animalType; private int ageInYears; private boolean isSafe; private Device collar; // Constructor public Livestock(String animalId, String animalType, int ageInYears) { this.animalId = animalId; this.animalType = animalType; this.ageInYears = ageInYears; this.isSafe = true; } // Method 1: Associate a physical IoT tracking device public void pairCollar(Device collar) { this.collar = collar; } // Method 2: Verify if the coordinates fall inside the grazing boundaries public boolean verifyLocation(double lat, double lng) { // Boundary coordinates simulation if (lat < -20.2 || lat > -20.0 || lng < 28.4 || lng > 28.7) { this.isSafe = false; return false; } this.isSafe = true; return true; } // Accessor methods public String getAnimalId() { return animalId; } public boolean getIsSafe() { return isSafe; } }

3.3 Farmer Class

package com.iot.livestock; import java.util.ArrayList; import java.util.List; public class Farmer { private String farmerId; private String fullName; private String contactNumber; private List<Livestock> myAnimals; // Constructor public Farmer(String farmerId, String fullName, String contactNumber) { this.farmerId = farmerId; this.fullName = fullName; this.contactNumber = contactNumber; this.myAnimals = new ArrayList<>(); } // Method 1: Register managed animal into system public void registerAnimal(Livestock animal) { if (animal != null && !this.myAnimals.contains(animal)) { this.myAnimals.add(animal); } } // Method 2: Handle warning alerts sent by SMS public void alertReceived(String alertMessage) { System.out.println("SMS sent to " + this.contactNumber + " -> Notification: " + alertMessage); } // Getters public String getFarmerId() { return farmerId; } public String getFullName() { return fullName; } }

4. Database Design (ERD)

This is the database layout. It maps farmers, their animals, the GPS tracker devices, sensor logs, and system alerts. Everything is normalized to 3rd Normal Form (3NF) to avoid repeating data.

Figure 3: Entity Relationship Diagram mapping tables and key constraints.

Database Table Descriptions

Table Name Relationship (Cardinality) Target Table Primary Key Foreign Key & Constraints
FARMERS 1 : Many LIVESTOCK farmer_id None
LIVESTOCK Many : 1 FARMERS livestock_id farmer_id links to FARMERS
DEVICES 1 : 1 LIVESTOCK device_id livestock_id links to LIVESTOCK [UNIQUE]
SENSOR_DATA Many : 1 DEVICES data_id device_id links to DEVICES
ALERTS Many : 1 LIVESTOCK alert_id livestock_id links to LIVESTOCK
